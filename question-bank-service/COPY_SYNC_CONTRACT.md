# Copy Version Sync (Question Bank provider contract)

All routes require the current JWT actor. A copy remains a separate Personal Question/QuestionSet. The provider never changes its source, an existing Public/Organization publication, or an Exam snapshot.

## Question copies

- `GET /questions/{id}/copy-sync` (owner): returns `questionId`, `localVersion`, `referenceSourceVersion`, `cursorRevision`, `latestSourceVersion`, `availability` (`AVAILABLE` or `UNAVAILABLE`), `localStatus`, and `changes[]`.
- Each `changes[]` entry has `field`, `sourceChanged`, `localChanged`, `conflict`, `redacted`, `reference`, `local`, `latest`. `OPTIONS`, `EXPECTED_ANSWER`, and `EXPLANATION` always have `redacted=true` and null comparison values; flags remain available. Other supported fields are `CATEGORY`, `CONTENT`, `QUESTION_TYPE`, `DIFFICULTY`.
- `POST /questions/{id}/copy-sync` (author-owner) body: `{"expectedLocalVersion":2,"expectedReferenceSourceVersion":1,"expectedCursorRevision":0,"expectedSourceVersion":3,"decisions":{"CONTENT":"KEEP_LOCAL","DIFFICULTY":"TAKE_SOURCE"}}`. Only selected changed fields advance their comparison baseline. Every conflicting field must have an explicit `KEEP_LOCAL` or `TAKE_SOURCE` decision. `TAKE_SOURCE` saves a normal new local DRAFT Question version; owner must activate it before Exam eligibility. `KEEP_LOCAL` preserves local content. The response is the refreshed preview.
- `GET /questions/{id}/copy-sync/history` (owner) lists audit events containing actor, local/source version, choices, and time. Existing `/questions/{id}/versions/{version}` remains the content revision history.

## Forked Public Question Sets

- `GET /question-sets/{id}/copy-sync` (owner): returns local/reference/latest Set versions, cursor revision, availability, `metadataChanges` for TITLE/DESCRIPTION, `itemChanges` with source/local IDs, source versions, positions, `kind` (`ADDED`, `UPDATED`, `REMOVED`) and local/conflict flags; `sourceReordered`, `localReordered`, `reorderConflict` describe relative order of common source items. No answer key is returned.
- `POST /question-sets/{id}/copy-sync` (author-owner) body: `{"expectedLocalVersion":1,"expectedReferenceSourceVersion":1,"expectedCursorRevision":0,"expectedSourceVersion":2,"decisions":{"TITLE":"TAKE_SOURCE","ITEM:<sourceQuestionId>":"TAKE_SOURCE","ORDER":"KEEP_LOCAL"}}`. Item choices are keyed with the literal `ITEM:` prefix and UUID. Selected source additions/updates become new independent DRAFT Personal Questions; selected removals remove membership only. Existing local Questions remain in history and are never deleted. Taking metadata/order/items saves a new frozen local Set version. Activate any new DRAFT children and update the Set through its existing API before publishing; no automatic approval/activation occurs.
- `GET /question-sets/{id}/copy-sync/history` (owner) lists audit choices. Existing `/question-sets/{id}/versions/{version}` remains Set version history.

The first comparison baseline is the original copied Question revision or Public Set publication; migration V10 stores only later resolution cursors and audit events, without rewriting older rows. `409` means stale local/source/cursor version, unresolved conflict, unavailable source on apply, archived local resource, or invalid Set content. `400` means malformed/unchanged decision. `404` hides inaccessible copies. A removed/archived/revoked source returns `UNAVAILABLE` in preview, with no latest values; apply fails closed. Personal/System source uses current ACTIVE version with resource access, Organization source requires current BANK_USE from provider, and Public source uses the latest publication in the original source series only if PUBLISHED. No foreign database is queried.
